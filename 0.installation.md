# Chapitre 0 : Installation et Configuration de l'environnement Genero BDL

Bienvenue dans ce **Chapitre 0**, le guide préalable indispensable à tout développement d'application avec **Genero BDL** (*Business Development Language*), la plateforme professionnelle éditée par Four Js Development Tools.

Avant d'écrire la moindre ligne de code BDL ou de concevoir des formulaires graphiques, il est crucial d'installer correctement les composants de l'écosystème, de télécharger les paquets requis, de configurer le gestionnaire de licence et de paramétrer les variables d'environnement nécessaires au bon fonctionnement de la DVM (*Dynamic Virtual Machine*).

---

## 1. Prérequis Système et Architecture d'Installation

L'écosystème Genero repose sur une architecture multi-composants. Selon votre rôle (développeur individuel, équipe distribuée ou administrateur de déploiement), l'installation peut être configurée en mode **Local / Standalone** ou en mode **Distant / Client-Serveur**.

### Composants Principaux de l'Architecture

- **Genero Studio (IDE)** : Environnement de développement intégré pour l'édition de code, le design de formulaires et le débogage.
- **Genero BDL (Compilateurs & DVM)** :
  - Compilateurs (`fglcomp`, `fglform`, `fgllink`).
  - Moteur d'exécution (`fglrun` / Dynamic Virtual Machine).
  - Couche d'accès indépendant aux SGBD (ODI - Open Database Interface).
  - Gestionnaire de licence local ou réseau (FLM).
- **Clients d'Affichage** :
  - **Genero Desktop Client (GDC)** : Client lourd natif pour poste de travail.
  - **Genero Application Server (GAS) & Browser Client (GBC)** : Moteur de rendu Web dans les navigateurs modernes.

### Systèmes d'Exploitation Supportés
La plateforme Genero Enterprise est certifiée sur un très large éventail de systèmes d'exploitation :
- **Microsoft Windows** (Postes de travail et versions Server 64-bit).
- **Linux** (Red Hat Enterprise Linux, CentOS, Rocky Linux, SUSE Linux Enterprise, Debian, Ubuntu).
- **UNIX d'entreprise** (IBM AIX, macOS pour le développement).

### Dépendances Logicielles et Clients SGBD
Selon les fonctionnalités ciblées, les paquets système et pilotes suivants doivent être installés avant l'installation de Genero :
1. **Pilotes / Clients de Base de Données (SGBD)** :
   - **IBM Informix** : Informix Client SDK (CSDK).
   - **Oracle** : Oracle Client / Instant Client.
   - **PostgreSQL** : Client `libpq`.
   - **MySQL / MariaDB** : Client `libmysqlclient` / `libmariadb`.
   - **Microsoft SQL Server** : Pilotes ODBC Microsoft ou FreeTDS.
   - *Note* : Genero Studio intègre nativement le pilote et le moteur **SQLite** pour le prototypage immédiat sans installation SGBD tierce.
2. **Environnement Java (JRE)** : Requis par certains composants du compilateur et du moteur de rapports (*Genero Report Engine*).
3. **Compilateur C (Optionnel)** : Un compilateur C natif (GCC sous Linux/UNIX, MSVC sous Windows) est requis uniquement si l'application utilise des extensions C personnalisées (`fglmkext`).

### Arborescence par Défaut des Répertoires d'Installation
Lors de l'installation des paquets téléchargés, les produits sont déployés par défaut dans des répertoires distincts (sous `/opt/fourjs/` sur Linux/UNIX ou `C:\fourjs\` sous Windows) :

| Composant | Variable d'environnement clé | Chemin par défaut (Linux) | Rôle principal |
| :--- | :--- | :--- | :--- |
| **Genero BDL** | `FGLDIR` | `/opt/fourjs/fgl` | Compilateurs (`fglcomp`, `fglform`), machine virtuelle (`fglrun`) et bibliothèques BDL. |
| **Genero Studio** | `GSTDIR` | `/opt/fourjs/gst` | Environnement de développement intégré (IDE), éditeur graphique de formulaires et débogueur. |
| **Genero Desktop Client** | `GDCDIR` | `/opt/fourjs/gdc` | Client d'affichage lourd pour poste de travail. |
| **Genero Application Server**| `GASDIR` | `/opt/fourjs/gas` | Serveur d'applications Web gérant le *Genero Browser Client* (GBC). |

### Modes d'Exécution dans Genero Studio
Lors du premier lancement de **Genero Studio (GST)**, vous pouvez choisir votre mode de travail :
- **Mode Local / Standalone** : Tout est installé sur votre poste local (Studio, DVM, GDC, SGBD SQLite/local). Idéal pour le développement individuel rapide.
- **Mode Distant / Client-Serveur** : Le client Genero Studio s'exécute localement, mais se connecte à un serveur Genero distant qui héberge la DVM, les fichiers sources du projet, les compilateurs et l'accès à la base de données centrale. Ce mode facilite le travail collaboratif en équipe.

## 3. Configuration et Activation de la Licence Genero

L'exécution des compilateurs (`fglcomp`) et de la machine virtuelle (`fglrun`) nécessite l'activation préalable d'un droit d'utilisation valide.

### Outil FLM (*Four Js License Manager*) vs Licence Locale
- **Licence Locale** : Convient pour un poste de développement unique. L'enregistrement s'effectue sur le poste de travail au moyen de l'assistant d'activation.
- **FLM (Four Js License Manager)** : Serveur de licences réseau centralisé qui attribue dynamiquement les jetons d'accès aux développeurs et serveurs de production.

### Activation de la Licence en Ligne de Commande (`fglwrt`)

L'outil d'administration `fglWrt` (fourni dans le répertoire d'installation de Genero BDL) permet d'effectuer les opérations courantes :

1. **Enregistrement en ligne** : Saisie du numéro de série et de la clé fournie par l'éditeur.
2. **Enregistrement hors-ligne** : Génération de la clé d'installation locale (`fglWrt -i`), puis saisie des clés de validation obtenues via le portail d'administration Four Js.
3. **Clé de maintenance** : Application de la clé de renouvellement de support (`fglWrt -m`).
4. **Vérification du statut** : Consultation des informations de licence et des utilisateurs actifs (`fglWrt -l`).

## 4. Variables d'Environnement et Fichier `FGLPROFILE`

Le bon fonctionnement de Genero BDL repose sur la configuration précise des variables d'environnement système et du fichier de profil applicatif.

### Variables d'Environnement Système Indispensables

Sous Linux/UNIX (dans `.bashrc` ou `.profile`) ou sous Windows (dans les Propriétés Système), définissez les variables fondamentales :

```bash
# Chemins d'installation principaux
export FGLDIR=/opt/fourjs/fgl
export PATH=$FGLDIR/bin:$PATH
export LD_LIBRARY_PATH=$FGLDIR/lib:$LD_LIBRARY_PATH

# Emplacement du profil applicatif par défaut
export FGLPROFILE=$FGLDIR/etc/fglprofile

# Chemins de recherche des formulaires (.42f) et modules (.42m)
export DBPATH=/app/forms:/app/modules
export FGLDBPATH=/app/forms:/app/modules

# Configuration des formats de dates et monnaies
export DBDATE=Y4MD-
export DBMONEY="."
```

### Le Fichier de Configuration `FGLPROFILE`

Le fichier **`FGLPROFILE`** définit les paramètres d'exécution de la DVM, notamment les connexions aux bases de données via la couche **ODI** (*Open Database Interface*) et les styles graphiques.

Exemple de fichier `fglprofile` pour une connexion PostgreSQL et Informix :

```ini
# --- Configuration de la base de données PostgreSQL ---
dbi.database.db_demo.driver = "dbmpgs"
dbi.database.db_demo.source = "db_demo@localhost:5432"
dbi.database.db_demo.username = "postgres"

# --- Configuration de la base de données Informix ---
dbi.database.db_prod.driver = "dbminf"
dbi.database.db_prod.source = "db_prod@ifx_server"

# --- Paramètres de rendu graphique GUI ---
gui.display.maintitle = "Application de Gestion Genero"
```

## 5. Validation de l'Installation et Chaîne de Compilation CLI

Pour vérifier que votre environnement Genero BDL est opérationnel, nous allons valider la chaîne de compilation en ligne de commande (*CLI*).

### Chaîne des Extensions de Fichiers Genero

- **`.4gl`** : Fichier source BDL, compilé par `fglcomp` en module bytecode **`.42m`**.
- **`.per`** : Fichier source de formulaire, compilé par `fglform` en formulaire binaire **`.42f`**.
- **`.msg`** : Fichier source de messages, compilé par `fglmkmsg` en fichier binaire **`.422`**.
- **`.42r`** : Exécutable final (*Runnable*) produit par le linker `fgllink` à partir des modules `.42m`.
- **`fglrun`** : Machine virtuelle (DVM) exécutant le fichier `.42r`.

### Test Pratique : Création et Exécution d'un Programme "Hello World"

#### Étape 1 : Rédaction du code source BDL (`hello.4gl`)
Créez un fichier texte nommé `hello.4gl` :

```4gl
MAIN
    DISPLAY "Félicitations ! Votre environnement Genero BDL est opérationnel !"
END MAIN
```

#### Étape 2 : Compilation du module BDL
Exécutez le compilateur BDL `fglcomp` :
```bash
fglcomp hello.4gl
```
*Résultat* : Le compilateur produit un fichier bytecode nommé **`hello.42m`**.

#### Étape 3 : Édition du lien exécutable
Exécutez le linker `fgllink` :
```bash
fgllink -o hello.42r hello.42m
```
*Résultat* : Le linker génère l'exécutable Genero **`hello.42r`** (*Runnable*).

#### Étape 4 : Exécution sur la DVM (*Dynamic Virtual Machine*)
Lancez le programme avec la machine virtuelle `fglrun` :
```bash
fglrun hello.42r
```
*Affichage attendu* :
```text
Félicitations ! Votre environnement Genero BDL est opérationnel !
```
