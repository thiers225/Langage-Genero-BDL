# Cours Complet : Les Bases du Langage de Programmation Genero BDL

Bienvenue dans ce cours complet consacré aux fondamentaux du langage **Genero BDL** (*Business Development Language*), développé par Four Js Development Tools. Ce langage de 4ème génération (4GL) a été conçu spécifiquement pour accélérer le développement d'applications de gestion d'entreprise robustes, portables et centrées sur la manipulation de bases de données relationnelles.

L'objectif de ce document est d'offrir un apprentissage progressif et méthodique, guidant le développeur depuis les concepts d'architecture jusqu'aux mécanismes avancés d'interaction utilisateur et d'intégration SQL.

---

## 1. Architecture et Principes Fondamentaux de Genero BDL

Pour comprendre Genero BDL, il convient d'abord d'appréhender son modèle architectural novateur, conçu pour séparer strictement la logique métier du code de présentation.

### La Séparation de la Logique Métier et de l'Interface Utilisateur
Contrairement aux langages traditionnels où le code d'affichage et le code applicatif sont souvent enchevêtrés, Genero BDL repose sur le concept d'**Interface Utilisateur Abstraite** (*Abstract User Interface* ou AUI). 

Comme le détaille le guide utilisateur du langage, l'application Genero BDL ne génère pas directement des éléments graphiques spécifiques à un système d'exploitation. Elle manipule un arbre XML logique appelé l'**arbre AUI**. Cet arbre représente l'ensemble des fenêtres, formulaires, champs et actions actifs. C'est le composant d'affichage (le client lourd *Genero Desktop Client* ou le client web *Genero Web Client*) qui lit cet arbre XML et effectue le rendu visuel approprié selon l'environnement d'exécution (Windows, Linux, macOS, navigateur Web ou terminal mobile).

Cette abstraction garantit le principe *"Write once, deploy anywhere"* : une même application compilée s'exécute sans aucune modification de code sur un poste de travail, un navigateur Web ou une tablette.

### La Machine Virtuelle Dynamique (DVM)
Au cœur du moteur d'exécution Genero se trouve la **DVM** (*Dynamic Virtual Machine*). La DVM agit comme un environnement d'exécution autonome qui prend en charge :
- L'exécution du p-code compilé de l'application.
- La gestion de la mémoire et de la pile d'appel.
- La communication bidirectionnelle en XML avec le client graphique.
- L'interfaçage avec le SGBD via la couche d'accès aux données.

### L'Interface Ouverte aux Bases de Données (ODI)
Le composant **ODI** (*Open Database Interface*) assure l'indépendance vis-à-vis du SGBD. L'ODI permet d'incorporer du SQL dans le code BDL tout en s'adaptant automatiquement aux spécificités de la base de données cible (IBM Informix, Oracle, PostgreSQL, Microsoft SQL Server, MySQL, SQLite, etc.). L'ODI traduit si nécessaire les requêtes SQL et gère les conversions de types de données grâce à des pilotes natifs.

## 2. Structure d'un Programme et Conventions Syntaxiques

Un projet Genero BDL est composé de plusieurs types de fichiers qu'il convient de compiler et d'assembler.

### Extensions de Fichiers Genero
Le tableau suivant récapitule les extensions de fichiers rencontrées lors du développement d'une application Genero BDL :

| Extension | Description / Rôle |
| :--- | :--- |
| `.4gl` | Fichier source de code BDL contenant la logique métier. |
| `.per` | Fichier de spécification de formulaire (*Form Specification File*), définissant la disposition visuelle. |
| `.42m` | Module de p-code compilé à partir d'un fichier `.4gl`. |
| `.42f` | Formulaire compilé au format XML à partir d'un fichier `.per`. |
| `.42r` | Application exécutable assemblée reliant les différents modules `.42m`. |

### Conventions Syntaxiques et Commentaires
Le langage Genero BDL est insensible à la casse des caractères. Toutefois, la convention universelle consiste à écrire les mots-clés du langage en majuscules et les identifiants (variables, fonctions) en minuscules.

Les commentaires peuvent être insérés de trois manières différentes :
- `--` (double tiré) ou `#` (croisillon) pour un commentaire sur une seule ligne.
- `{ ... }` (accolades) pour isoler un bloc de commentaires s'étendant sur plusieurs lignes.

```genero
-- Ceci est un commentaire sur une ligne
# Ceci est également un commentaire
{
   Ceci est un bloc de commentaire
   s'étendant sur plusieurs lignes.
}
```

### Blocs de Programme Fonctionnels
Un fichier source `.4gl` est structuré en plusieurs blocs de programme distincts :
1. **Bloc `MAIN`** : Point d'entrée obligatoire de toute application. Il ne peut y avoir qu'un seul bloc `MAIN` par application exécutable.
2. **Blocs `FUNCTION`** : Sous-programmes réutilisables contenant la logique applicative.
3. **Blocs `REPORT`** : Routines spécialisées dans la mise en page et la génération d'états imprimables.

Voici l'exemple d'un programme BDL minimal :

```genero
MAIN
   DISPLAY "Bienvenue dans le cours Genero BDL !"
   CALL afficher_salutation("Développeur")
END MAIN

FUNCTION afficher_salutation(nom)
   DEFINE nom STRING
   DISPLAY "Bonjour ", nom CLIPPED, " !"
END FUNCTION
```

## 3. Types de Données Primitifs et Déclaration de Variables

Comme indiqué dans le manuel de référence des bases de BDL, Genero propose un ensemble complet de types de données primitifs alignés sur les standards des bases de données relationnelles.

### Types Primitifs Principaux
- **Numériques entiers** : `SMALLINT` (16-bit), `INTEGER` (32-bit), `BIGINT` (64-bit), `TINYINT`.
- **Numériques décimaux** : `DECIMAL(p,s)` ou `NUMERIC(p,s)` (précision fixe), `MONEY(p,s)` (spécifique aux valeurs monétaires), `FLOAT`, `SMALLFLOAT`.
- **Chaînes de caractères** :
  - `CHAR(n)` : Chaîne de longueur fixe de $n$ caractères.
  - `VARCHAR(n)` : Chaîne de longueur variable limitée à $n$ caractères.
  - `STRING` : Chaîne dynamique sans limitation fixe préalable de taille.
- **Dates et Heures** :
  - `DATE` : Stocke une date (jour, mois, année).
  - `DATETIME qual1 TO qual2` : Stocke un horodatage précis (ex: `DATETIME YEAR TO SECOND`).
  - `INTERVAL qual1 TO qual2` : Représente une durée ou un écart temporel.
- **Booléen et Objets/LOB** : `BOOLEAN` (`TRUE`, `FALSE`), `TEXT` (blocs de texte volumineux), `BYTE` (données binaires).

### Constantes Prédéfinies
Le langage fournit plusieurs constantes système essentielles :
- `NULL` : Représente une valeur absente ou non définie.
- `TRUE` et `FALSE` : Valeurs booléennes littérales.
- `NOTFOUND` : Indicateur de fin de parcours lors de la recherche dans un jeu de résultats SQL.

### Déclaration de Variables (`DEFINE`) et Typage Dynamique (`LIKE`)
Les variables sont déclarées à l'aide de l'instruction `DEFINE`. Il est également possible d'utiliser le mot-clé `LIKE` pour associer automatiquement le type d'une variable à la définition d'une colonne de la base de données.

```genero
MAIN
   DEFINE v_compteur INTEGER
   DEFINE v_nom VARCHAR(50)
   DEFINE v_solde MONEY(10,2)
   DEFINE v_date_creation DATE
   
   -- Typage dynamique basé sur le schéma de la base de données
   DEFINE v_client_id LIKE clients.cli_id
   
   LET v_compteur = 10
   LET v_nom = "Dupont"
   LET v_solde = 1250.50
   LET v_date_creation = TODAY
   
   DISPLAY "Client : ", v_nom CLIPPED, " Solde : ", v_solde
END MAIN
```

### Portée des Variables
- **Variables Locales** : Déclarées à l'intérieur d'une fonction ou du bloc `MAIN`, accessibles uniquement dans ce bloc.
- **Variables de Module (`PRIVATE` / `PUBLIC`)** : Déclarées au sommet d'un fichier `.4gl` (en dehors de toute fonction).
- **Variables Globales (`GLOBALS`)** : Déclarées dans un bloc `GLOBALS ... END GLOBALS` ou incluses depuis un fichier externe de globales, accessibles dans l'ensemble des modules de l'application.

## 4. Structures de Données Avancées

Pour gérer des données complexes et des listes d'enregistrements, Genero BDL offre des structures élaborées.

### Les Enregistrements (`RECORD`)
Un `RECORD` est une structure regroupant plusieurs champs nommés, pouvant chacun avoir leur propre type de données.

```genero
MAIN
   -- Déclaration explicite d'un enregistrement
   DEFINE r_client RECORD
      id INTEGER,
      nom VARCHAR(40),
      email STRING,
      actif BOOLEAN
   END RECORD

   -- Déclaration basée sur la structure d'une table de la base de données
   DEFINE r_article RECORD LIKE articles.*

   LET r_client.id = 101
   LET r_client.nom = "Martin"
   LET r_client.actif = TRUE

   DISPLAY "ID : ", r_client.id, " Nom : ", r_client.nom CLIPPED
END MAIN
```

### Les Tableaux (`ARRAY`)
Genero BDL distingue deux catégories de tableaux :
1. **Tableaux Statiques** : Possèdent une taille maximale fixe définie à la compilation.
2. **Tableaux Dynamiques** : Alloués dynamiquement en mémoire sans limite préfixée, manipulés via des méthodes orientées objet.

```genero
MAIN
   -- Tableau statique de 100 entiers
   DEFINE t_statique ARRAY[100] OF INTEGER
   
   -- Tableau dynamique d'enregistrements
   DEFINE t_clients DYNAMIC ARRAY OF RECORD
      id INTEGER,
      nom STRING
   END RECORD

   -- Utilisation des méthodes de tableaux dynamiques
   CALL t_clients.appendElement()
   LET t_clients[1].id = 1
   LET t_clients[1].nom = "Durand"

   CALL t_clients.appendElement()
   LET t_clients[2].id = 2
   LET t_clients[2].nom = "Lefebvre"

   DISPLAY "Nombre d'éléments : ", t_clients.getLength()
END MAIN
```

### Définition de Types Personnalisés (`TYPE`)
Le mot-clé `TYPE` permet de définir des types réutilisables dans tout le programme, simplifiant la déclaration de structures complexes.

```genero
TYPE t_adresse RECORD
   rue STRING,
   code_postal CHAR(5),
   ville STRING
END RECORD

MAIN
   DEFINE addr1 t_adresse
   LET addr1.rue = "10 Rue de la Paix"
   LET addr1.code_postal = "75002"
   LET addr1.ville = "Paris"
END MAIN
```

## 5. Structures de Contrôle et Gestion des Exceptions

### Instructions Conditionnelles
Le langage propose les structures conditionnelles classiques `IF` et `CASE`.

```genero
IF v_solde > 0 THEN
   DISPLAY "Compte créditeur"
ELSEIF v_solde = 0 THEN
   DISPLAY "Compte nul"
ELSE
   DISPLAY "Compte débiteur"
END IF

CASE v_code_statut
   WHEN "A"
      DISPLAY "Statut : Actif"
   WHEN "I"
      DISPLAY "Statut : Inactif"
   OTHERWISE
      DISPLAY "Statut : Inconnu"
END CASE
```

### Boucles d'Itération
- **Boucle `FOR`** : Pour un nombre d'itérations connu.
- **Boucle `WHILE`** : Basée sur une condition booléenne.

```genero
-- Boucle FOR
FOR i = 1 TO 5
   DISPLAY "Ligne : ", i
END FOR

-- Boucle WHILE
LET i = 1
WHILE i <= 3
   DISPLAY "Compteur WHILE : ", i
   LET i = i + 1
END WHILE
```

### Appel de Fonctions et Valeurs de Retour
Les fonctions peuvent recevoir des paramètres et retourner plusieurs valeurs simultanément.

```genero
MAIN
   DEFINE v_res INTEGER
   DEFINE v_err BOOLEAN
   
   CALL calculer_surface(10, 15) RETURNING v_res, v_err
   IF NOT v_err THEN
      DISPLAY "Surface calculée : ", v_res
   END IF
END MAIN

FUNCTION calculer_surface(p_largeur, p_hauteur)
   DEFINE p_largeur, p_hauteur INTEGER
   IF p_largeur <= 0 OR p_hauteur <= 0 THEN
      RETURN 0, TRUE
   END IF
   RETURN (p_largeur * p_hauteur), FALSE
END FUNCTION
```

### Gestion des Erreurs (`WHENEVER` et `TRY ... CATCH`)
Genero BDL propose deux mécanismes pour intercepter et traiter les erreurs d'exécution ou les exceptions SQL :
1. **Directive `WHENEVER ERROR`** : Définit le comportement global en cas d'erreur (ex: `WHENEVER ERROR CONTINUE` ou `WHENEVER ERROR CALL ma_fonction_erreur`).
2. **Bloc `TRY ... CATCH`** : Permet une interception locale et structurée des exceptions.

```genero
MAIN
   TRY
      -- Tentative d'opération risquée
      DATABASE custdemo
      DISPLAY "Connexion réussie !"
   CATCH
      DISPLAY "Erreur de connexion à la base de données ! Code : ", STATUS
   END TRY
END MAIN
```

## 6. Intégration SQL et Gestion des Bases de Données

L'une des plus grandes forces de Genero BDL réside dans son intégration transparente du langage SQL pour interagir avec les SGBD relationnels.

### Connexion et SQL Statique
Il est possible d'exécuter directement des requêtes SQL statiques (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) intégrées au code BDL. Les variables BDL sont préfixées par deux-points (`:`) lorsqu'elles sont utilisées dans des requêtes SQL complexes ou passées directement.

```genero
MAIN
   DEFINE v_cli_id INTEGER
   DEFINE v_cli_nom VARCHAR(50)

   DATABASE custdemo

   -- Requête SELECT simple pour une seule ligne
   SELECT cli_nom INTO v_cli_nom
      FROM clients
      WHERE cli_id = 101

   IF STATUS = 0 THEN
      DISPLAY "Nom du client : ", v_cli_nom CLIPPED
   ELSEIF STATUS = NOTFOUND THEN
      DISPLAY "Client non trouvé."
   END IF
END MAIN
```

### Curseurs SQL et Traitement des Jeux de Résultats
Lorsque la requête retourne plusieurs lignes, l'utilisation d'un **curseur** est nécessaire. L'instruction `FOREACH` simplifie la lecture ligne par ligne d'un curseur.

```genero
MAIN
   DEFINE r_cli RECORD
      id INTEGER,
      nom VARCHAR(50)
   END RECORD

   DATABASE custdemo

   -- Déclaration et parcours d'un curseur SQL
   DECLARE c_clients CURSOR FOR
      SELECT cli_id, cli_nom FROM clients ORDER BY cli_id

   FOREACH c_clients INTO r_cli.id, r_cli.nom
      DISPLAY "ID: ", r_cli.id, " Nom: ", r_cli.nom CLIPPED
   END FOREACH
END MAIN
```

### SQL Dynamique (`PREPARE` / `EXECUTE`)
Pour construire des requêtes de manière dynamique à l'exécution :

```genero
MAIN
   DEFINE v_sql STRING
   DEFINE v_count INTEGER

   DATABASE custdemo
   LET v_sql = "SELECT COUNT(*) FROM clients WHERE cli_ville = ?"

   PREPARE stmt1 FROM v_sql
   EXECUTE stmt1 USING "Paris" INTO v_count

   DISPLAY "Nombre de clients à Paris : ", v_count
   FREE stmt1
END MAIN
```

### Gestion des Transactions
Les opérations d'écriture en base doivent être isolées au sein de transactions SQL :

```genero
BEGIN WORK
   UPDATE comptes SET solde = solde - 100 WHERE cpt_id = 10
   UPDATE comptes SET solde = solde + 100 WHERE cpt_id = 20
IF STATUS = 0 THEN
   COMMIT WORK
   DISPLAY "Transfert validé !"
ELSE
   ROLLBACK WORK
   DISPLAY "Erreur, annulation du transfert !"
END IF
```

## 7. Instructions d'Interaction Utilisateur (Dialogues BDL)

Comme l'illustre le tutoriel d'application Genero BDL, le langage fournit un ensemble d'instructions haut niveau appelées **dialogues**, qui gèrent l'interaction entre l'utilisateur et les formulaires graphiques (`.per`).

### Formulation de Menus (`MENU`)
L'instruction `MENU` permet de créer des menus d'options interactifs.

```genero
MENU "Menu Principal"
   COMMAND "Client", "Gérer les clients"
      DISPLAY "Option Client sélectionnée"
   COMMAND "Quitter", "Fermer l'application"
      EXIT MENU
END MENU
```

### Saisie de Données (`INPUT` et `INPUT BY NAME`)
L'instruction `INPUT BY NAME` lie directement les champs d'un formulaire aux variables BDL correspondantes.

```genero
MAIN
   DEFINE r_client RECORD
      nom VARCHAR(40),
      email VARCHAR(80)
   END RECORD

   OPEN WINDOW w_cli WITH FORM "client_form"

   -- Saisie interactive guidée par les évènements
   INPUT BY NAME r_client.nom, r_client.email
      BEFORE INPUT
         DISPLAY "Début de la saisie"
      ON ACTION valider
         ACCEPT INPUT
   END INPUT

   CLOSE WINDOW w_cli
END MAIN
```

### Recherche par l'Exemple (`CONSTRUCT`)
L'instruction `CONSTRUCT` permet à l'utilisateur de saisir des critères de recherche sur un formulaire pour générer automatiquement une clause SQL `WHERE`.

```genero
MAIN
   DEFINE v_where STRING

   OPEN WINDOW w_qbe WITH FORM "client_search"

   CONSTRUCT BY NAME v_where ON clients.cli_nom, clients.cli_ville

   DISPLAY "Clause WHERE générée : ", v_where CLIPPED
   CLOSE WINDOW w_qbe
END MAIN
```

### Affichage et Édition de Listes (`DISPLAY ARRAY` et `INPUT ARRAY`)
Pour afficher et manipuler des données sous forme de tableau ou de grille :
- `DISPLAY ARRAY` : Affiche une liste d'enregistrements (lecture seule ou sélection).
- `INPUT ARRAY` : Permet l'édition, l'ajout et la suppression de lignes directement dans la grille.

```genero
MAIN
   DEFINE t_articles DYNAMIC ARRAY OF RECORD
      code STRING,
      designation STRING,
      prix MONEY(8,2)
   END RECORD

   -- Remplissage du tableau...
   OPEN WINDOW w_list WITH FORM "article_list"

   DISPLAY ARRAY t_articles TO s_articles.*
      ON ACTION ajouter
         DISPLAY "Action d'ajout déclenchée"
   END DISPLAY

   CLOSE WINDOW w_list
END MAIN
```

### Les Dialogues Multiples (`DIALOG`)
L'instruction `DIALOG` rassemble sous une même boucle d'évènements plusieurs sous-dialogues (`INPUT`, `DISPLAY ARRAY`, `CONSTRUCT`), permettant de créer des interfaces complexes modernes de type maître-détail sur un seul écran.
